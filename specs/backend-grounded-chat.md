# Диалог с поиском и AI

Backend принимает вопрос от пользователя с серверной сессией. Диалог привязан к владельцу, команде и роли. Вопрос записывается до обращения к провайдеру. Повтор того же `client_message_id` с тем же текстом после сбоя продолжает генерацию. После успешного ответа повтор возвращает сохранённый ответ. Одновременно в одном диалоге выполняется одна генерация. Её аренда истекает после сбоя процесса.

При повторном открытии диалога интерфейс предлагает вручную повторить последний сохранённый вопрос, если на него ещё нет ответа. Запрос использует прежний `client_message_id`, поэтому потеря ответа или перезагрузка не создают копию вопроса. Если генерация ещё идёт, действуют обычные правила конкурентного повтора.

Поиск выполняется для команды и роли из сессии. Модель получает до трёх фрагментов, ограниченную историю вопросов и доступные учебные ресурсы. ID источников и черновик проверяются на backend. Предложение о заявке сохраняется как черновик. Обоснование переносится из сообщения пользователя, если модель вернула его точной цитатой. Иначе пользователь заполняет поле перед подтверждением. Для отправки по-прежнему нужно отдельное подтверждение актуальной версии. Статус заявки интерфейс читает из API операций. В модель передаётся только подтверждённый сервисом статус текущего диалога.

В ответе `POST /api/conversations/{id}/messages` и сообщениях истории доступны `source_ids`, `sources` и `clarifying_question`. Метаданные источника содержат ID фрагмента и документа, название, URL, тип и версию. `GET /api/documents/{id}` заново проверяет ACL. Перед выдачей сохранённого ответа проверяются все входные фрагменты. Если фрагмент изменился или доступ исчез, старый ответ скрывается. При смене команды или роли старый диалог отвечает 404.

При открытии цитаты интерфейс выделяет соответствующий фрагмент в разрешённом документе. Для материалов с HTTPS-адресом показывает ссылку на оригинал. Учебная политика может содержать только локальный текст.

Короткий вопрос без названия инструмента, например «А какая роль нужна?», может продолжать предыдущую тему. Для такого вопроса сервер ищет правила о роли только для одного учебного ресурса, однозначно названного в последнем содержательном сообщении. Если ресурс не определён, помощник уточняет его локально. Если инструкция о роли не найдена, он сообщает об этом. Вопрос о роли не создаёт черновик заявки.

Команда «Проверить статус заявки» отвечает из базы без поиска и модели. В первую очередь она проверяет заявку текущего диалога. Если в этом диалоге заявки нет, показывает статус единственной подтверждённой заявки пользователя. При нескольких заявках предлагает выбрать нужную в разделе «Доступы». Ответ в истории сохраняет статус на момент проверки.

Критерии проверки: источники с чужой команды отсутствуют в запросе к модели, подставленный ID отклоняется, после сбоя модели повтор сохраняет одну пару сообщений, черновик не создаёт операцию до подтверждения. Без ключа провайдера команда может запустить явный учебный режим.
