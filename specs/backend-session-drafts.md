# Серверная сессия, диалог и подтверждение заявки

Первый срез B1–B2 позволяет проверить сценарий без внешнего AI и сервиса заявок. Backend принимает Bearer-токен тестового аккаунта. Профиль, команда и роль загружаются из PostgreSQL. Два учебных аккаунта имеют раздельные диалоги, черновики и операции.

| Маршрут | Поведение |
| --- | --- |
| `GET /api/me` | Возвращает `id`, `team_id`, `role` и `name` текущего пользователя |
| `POST /api/conversations` | Создаёт диалог с владельцем из сессии и возвращает `{id}` |
| `POST /api/conversations/{id}/messages` | Сохраняет вопрос и ответ с `client_message_id`. Повтор идентификатора и того же текста возвращает исходный ответ. Тот же идентификатор с другим текстом даёт 409 |
| `GET /api/conversations/{id}` | Возвращает `{id,messages,draft,operation}` для восстановления после перезагрузки |
| `PATCH /api/drafts/{id}` | Принимает `expected_version` и изменяемые поля `tool_id`, `resource_id`, `justification`. Проверяет каталог команды, сохраняет новую версию |
| `POST /api/drafts/{id}/confirm` | Принимает `version`. Сохраняет одну операцию `queued` и снимок данных. Повтор той же версии возвращает ту же операцию |
| `GET /api/operations` | Возвращает `{operations}` с подтверждёнными заявками пользователя из всех его диалогов. Каждая запись содержит операцию, `tool_id` и `resource_id`. Новые заявки идут первыми |
| `GET /api/operations/{id}` | Показывает очередь и следующий шаг. До доставки `external_id` и `service_status` пусты |

Учебный ответ явно обозначен и предлагает черновик запроса GitLab своей команды. Обоснование заполняет пользователь. Черновик один на диалог. Для подтверждения нужны актуальная версия, разрешённый ресурс и заполненное обоснование. После подтверждения черновик закрыт для редактирования. Источник пользователя, команда и статус не принимаются из текста или JSON клиента.

API возвращает 401 при отсутствующей или просроченной сессии, 404 для чужих и неизвестных объектов, 409 для конфликтов версий и повторов с другим содержимым, 422 для неправильных полей. Ошибка содержит `{error:{code,message},request_id}`.

Критерии проверки: после перезапуска сохранены диалог и очередь. Повтор отправки сообщения не удваивает историю. Два подтверждения одной версии не удваивают операцию. Токен другой команды не может прочитать или изменить объект. Доставка и получение статуса из сервиса заявок относятся к следующему срезу.

[Доставка и опрос статуса](backend-access-delivery.md) описаны в отдельной спецификации.

[Диалог с поиском, источниками и AI](backend-grounded-chat.md) подключает эти маршруты к реальному адаптеру модели.

Раздел «Доступы» загружает заявки по сессии и обновляет статусы незавершённых операций. Новый диалог или новая вкладка не скрывают уже подтверждённую заявку. Смена пользователя, команды или роли не переносит заявки в новый контекст. Пока нет подтверждённых заявок, API возвращает пустой массив.
