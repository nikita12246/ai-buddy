# Доставка заявки в учебный сервис

После явного подтверждения API сохраняет неизменяемый снимок и уникальный ключ операции. Воркер отправляет заявку отдельно от HTTP-запроса пользователя. Сервис заявок — отдельный HTTP-процесс с таблицей в схеме `mock_access`. API общается с ним через HTTP.

| Вызов | Ожидаемый результат |
| --- | --- |
| `POST /requests` | Bearer-токен сервиса, `Idempotency-Key` и снимок. Создаёт заявку с `pending_approval`. Повтор ключа и тела возвращает прежний номер. Другое тело даёт 409 |
| `GET /requests/by-key/{key}` | Возвращает существующую заявку для сверки после неоднозначной отправки |
| `GET /requests/{id}` | Возвращает бизнес-статус заявки |
| `PATCH /requests/{id}/decision` | Отдельный токен оператора демо. Переводит заявку в `approved` или `rejected` |

До первого ответа пользователь видит `queued` или `sending`. При сетевой ошибке видит `reconciling`. Воркер сначала ищет заявку по ключу. Повторить отправку можно только с тем же ключом и снимком, если сервис не нашёл заявку. По истечении аренды `sending` также восстанавливается через сверку. Число попыток доставки ограничено. Подтверждённый ответ сервиса сохраняет `external_id` и `service_status`, после чего состояние доставки — `delivered`. Пока бизнес-статус `pending_approval`, воркер опрашивает сервис. Терминальные статусы останавливают опрос.

Интерфейс показывает номер заявки только после получения `external_id`. До этого показываются состояние доставки и следующий шаг.

Когда попытки автоматической сверки исчерпаны и действующей аренды воркера больше нет, API выставляет `needs_manual_check`. Интерфейс прекращает автоматический опрос такой заявки, показывает, что результат нужно уточнить, и оставляет ручное обновление списка. Неопределённый исход сохраняется.

Для заявки с номером можно скопировать сводку для наставника. Она включает ресурс, номер, текущий статус и следующий шаг. При недоступном буфере обмена текст можно выделить и скопировать вручную.

Проверки: потерять ответ после записи, перезапустить воркер и восстановить тот же ID. Повтор HTTP-запроса с тем же ключом сохраняет одну строку. Решение оператора отображается через API после опроса. Токен API и токен решения проверяются на разных маршрутах. Клиент приложения не может выставить себе статус.
