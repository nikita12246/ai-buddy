# Сценарии для демо данных

Учебные команды, ресурсы и заявки Atlas и Orbit вымышлены. Статусы заявки в приложении должны приходить из сервиса заявок.

| Сценарий | Кто спрашивает и что пишет | Что проверяем |
| --- | --- | --- |
| Чек-лист | Стажёр. «Что записывать после встреч с наставником в первую неделю?» | Ответ с опорой на `avito-checklist-general-r5`. Ссылка открывает нужную строку |
| Новый инструмент | Стажёр. «Где в Sentry посмотреть stack trace и breadcrumbs?» | Ответ называет детали события и ссылается на `vendor-sentry-issues-s1` с пометкой о справке производителя |
| Учебный доступ | Стажёр Orbit. «Какой README читать для первого задания и какая роль нужна?» | Указаны `orbit-training-repo` и Reporter из `orbit-first-task-r1`. Доступ и подтверждение заявки относятся к учебной команде |
| Недостаточно сведений | Стажёр. «Кто сегодня дежурный SPT по моему юниту?» | Можно объяснить, зачем существует SPT. Имя и контакт требуют актуального расписания |
| Изоляция команд | Стажёр Atlas. «Покажи инструкцию по приватному GitLab Orbit» | В выдаче и цитатах нет документов Orbit. Прямое открытие документа тоже ограничено. Поведение живой модели проверяется отдельно |

## Маршрут новичка

[Учебный маршрут](demo-route.json) описывает восемь шагов для Orbit. Часть шагов опирается на пункты настоящего чек-листа, часть демонстрирует путь по синтетическим инструкциям. Связи между шагами заданы для демо. Они не представляют обязательную последовательность для сотрудников Авито.

У каждого шага есть критерий завершения. Флаг `completion_kind: request_approved` предполагает, что backend подтвердил факт одобрения. Шаг чтения README доступен после него. У остальных шагов проверка по отметке стажёра, наставника или факту отправки заявки. Файл предоставляет структуру данных для демо. Хранение прогресса и отображение остаются задачами интеграции.
